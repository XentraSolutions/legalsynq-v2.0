ARCHITECTURAL PRINCIPLE

Synq Intake remains:
- tenant-bound
- product-neutral
- independently deployable
- source-preserving
- profile-driven

B06 adds a second intake path but must converge on the same canonical artifact pipeline.

LOCKED HIGH-LEVEL FLOW

EMAIL:
TenantIntakeSource
-> InboundEmail
-> IntakeArtifact
-> Documents Service

MANUAL:
Authenticated Tenant User
-> Manual Intake Submission
-> IntakeArtifact
-> Documents Service

Both paths must converge on the same artifact/document-management model.

OBJECTIVE

Implement two operational capabilities:

A. Manual Intake
Allow authorized tenant users to manually submit one or more files into Synq Intake, preserve submission provenance, validate B02 processing profile configuration, create/reuse B05-style IntakeArtifacts, upload files through Documents Service, expose submission state, and allow retry of failed artifacts.

B. Source Management
Expose the existing B03 source-management capability as a usable tenant-administration experience for listing, creating, editing, enabling/disabling, default selection, validation, connector testing, provider capability inspection, and source-health/status inspection.

The implementation must not classify or interpret document business meaning.

7. SUBMISSION LIFECYCLE
==================================================

Use a simple deterministic lifecycle.

Recommended:

DRAFT
SUBMITTED
PROCESSING
READY
PARTIAL
FAILED
CANCELLED

Do not introduce AI/review states.

READY means:
- submission metadata persisted;
- all eligible artifacts processed successfully;
- durable Documents references available;
- submission is ready for later B07 classification.

PARTIAL means:
- some artifacts completed;
- at least one eligible artifact failed/skipped according to policy.

FAILED means:
- no eligible artifact completed successfully or submission cannot proceed.
