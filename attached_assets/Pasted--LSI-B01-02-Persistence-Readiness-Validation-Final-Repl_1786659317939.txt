10. HEALTH / READINESS VALIDATION
==================================================

Validate both positive and negative behavior.

A. Healthy database state

Start Synq Intake with valid local/disposable MySQL configuration.

Validate:

GET /health

Expected:
HTTP 200 or repository-standard healthy response.

Validate:

GET /health/ready

Expected:
HTTP 200
Healthy readiness state.

Record actual status and relevant sanitized body.

B. Database unavailable state

Then intentionally make the Intake database unavailable in a safe local/disposable manner.

Examples:

- stop the disposable MySQL container/process;
- temporarily use an invalid local port;
- temporarily point to an unavailable local host.

Validate:

GET /health

Expected:
service process remains healthy according to LegalSynq liveness convention.

Validate:

GET /health/ready

Expected:
not-ready result, typically HTTP 503.

C. Restore database

Restore valid DB connectivity and prove readiness returns to healthy state.

This should demonstrate:

liveness
!=
readiness

Do not weaken readiness checks merely to force HTTP 200.
