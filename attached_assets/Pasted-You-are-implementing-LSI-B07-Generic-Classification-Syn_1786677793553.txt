ARCHITECTURAL PRINCIPLE

Synq AI must remain a generic platform capability.

The framework must support:

Tenant
-> AI Policy
-> Provider / Model
-> Classification Profile
-> IntakeArtifact
-> Classification Result

The first classification profile is lien-oriented, but the AI architecture itself must not be hardcoded to SynqLien.

LOCKED PROCESSING FLOW

Email or Manual Intake
-> IntakeArtifact COMPLETED
-> AI classification request
-> Synq AI provider abstraction
-> structured classification result
-> confidence/evidence/model provenance

Classification answers:

“What kind of document/artifact is this?”

B07 MUST NOT answer:

- patient identity;
- provider identity;
- facility identity;
- case number;
- lien balance;
- settlement amount;
- accident date;
- claim validity;
- whether a lien should be created;
- whether an item should be approved.

Those belong to later bundles.
