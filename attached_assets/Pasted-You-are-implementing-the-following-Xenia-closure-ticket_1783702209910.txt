9. HARDEN SSRF PROTECTION
--------------------------------------------------

Replace simple host-string checks with resolved-address validation.

Required behavior:

1. Validate hostname syntax.
2. Resolve DNS using a controlled resolver abstraction.
3. Validate every returned IP address.
4. Reject the host if any candidate address is unsafe unless the security design explicitly pins a safe address and excludes unsafe candidates.
5. Connect only to an address that passed validation.
6. Avoid resolving again implicitly to an unvalidated address.
7. Revalidate immediately before connection.
8. Enforce allowed ports.
9. Enforce timeout.
10. Do not follow redirects.
11. Do not accept arbitrary URL schemes.
12. Never disable TLS certificate validation.

Block at minimum:

IPv4:
- 0.0.0.0/8
- 10.0.0.0/8
- 100.64.0.0/10 where policy requires
- 127.0.0.0/8
- 169.254.0.0/16
- 172.16.0.0/12
- 192.0.0.0/24
- 192.0.2.0/24
- 192.168.0.0/16
- 198.18.0.0/15
- 198.51.100.0/24
- 203.0.113.0/24
- 224.0.0.0/4
- 240.0.0.0/4
- 255.255.255.255

IPv6:
- ::
- ::1
- fc00::/7
- fe80::/10
- ff00::/8
- IPv4-mapped IPv6 representations of blocked IPv4 ranges
- Documentation and benchmark ranges where appropriate

Cloud metadata:
- 169.254.169.254
- metadata.google.internal
- AWS, Azure, GCP, and other known metadata hostnames
- Platform-configured metadata aliases

Add a development-only override only if essential.

It must:
- Be disabled by default
- Require Development environment
- Be explicit
- Be documented
- Never be active in production
