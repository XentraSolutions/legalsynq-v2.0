====================================================
IMPLEMENTATION TASKS
====================================================

# 1. Inspect Tenant/Product Lifecycle Implementation Points

Before coding, identify and document:

- tenant creation method(s)
- tenant activation method(s)
- tenant suspension/deactivation method(s)
- tenant closure/archive method(s)
- product enablement method(s)
- product disablement method(s)
- current audit/logging behavior
- available tenant id, product key, actor id, and correlation id sources
- existing DI registration patterns

Document findings in the report.

# 2. Wire Tenant Lifecycle Commerce Notifications

Add Commerce lifecycle notification calls where safe.

Target events:

- tenant created → `CommerceEventTypes.TenantCreated`
- tenant activated → `CommerceEventTypes.TenantActivated`
- tenant suspended/deactivated → `CommerceEventTypes.TenantSuspended`
- tenant closed/archived → `CommerceEventTypes.TenantClosed`

Requirements:

- use `ICommerceLifecycleNotifier`
- create `CommerceLifecycleEvent`
- set `HostPlatformKey = "legalsynq"`
- set `ExternalTenantId` to canonical tenant ID
- set `OccurredAtUtc`
- include `CorrelationId` where available
- include safe metadata where useful
- do not block tenant lifecycle if notifier fails
- do not create billing accounts automatically unless already supported by an existing safe API and explicitly needed

# 3. Wire Product Lifecycle Commerce Notifications

Add Commerce lifecycle notification calls to product provisioning flows.

Target events:

- product enabled → `CommerceEventTypes.ProductEnabled`
- product disabled → `CommerceEventTypes.ProductDisabled`

Requirements:

- include tenant ID
- include product key
- include correlation ID where available
- use `ICommerceLifecycleNotifier`
- do not block product provisioning if notifier fails
- do not add entitlement enforcement in this ticket
- do not auto-create subscriptions in this ticket

# 4. Ensure Noop-First Safety

Commerce lifecycle integration must remain safe by default.

Requirements:

- `CommerceIntegration:Enabled=false` must not change lifecycle behavior
- noop notifier must remain valid fallback
- lifecycle calls must not throw back into primary flows
- services must still start without Commerce running
- missing Commerce configuration must not break tenant/product lifecycle

# 5. Add Optional Audit / Readiness Visibility

Where existing patterns support it, add safe visibility for Commerce lifecycle integration.

Examples:

- debug/info log when notification is skipped/noop
- audit event when lifecycle notification is attempted/sent/failed
- readiness telemetry indicating lifecycle notifier wired

Rules:

- do not introduce a new audit system
- do not add noisy logs
- do not expose tokens/secrets
- if audit pattern is unclear, defer and document

# 6. Add Tests / Validation

Add tests where practical.

Recommended tests:

- tenant create emits Commerce lifecycle event through mock notifier
- tenant suspend emits correct Commerce event type
- product enable emits ProductEnabled event with product key
- notifier failure does not fail primary lifecycle operation
- noop/default behavior preserves existing lifecycle behavior
- CommerceIntegration disabled mode does not require Commerce service

If automated tests are not practical:
- document manual validation steps.
