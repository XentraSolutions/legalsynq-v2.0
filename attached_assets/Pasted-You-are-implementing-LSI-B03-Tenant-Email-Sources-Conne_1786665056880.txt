ARCHITECTURAL PRINCIPLE
Synq Intake remains:
- tenant-bound
- product-neutral
- independently deployable

LOCKED TENANT EMAIL INVARIANT
Every configured Synq Intake email address belongs to exactly one tenant.

For all future inbound email processing, the required sequence is:

Inbound recipient address
-> registered TenantIntakeSource
-> authoritative TenantId
-> source Purpose
-> source ProcessingProfileCode
-> B02 configuration/profile resolution
-> processing

Tenant identity MUST NEVER be inferred from:
- sender email
- sender domain
- subject
- email body
- patient
- provider
- law firm
- facility
- attachment content
- document metadata
- AI classification
- AI extraction
- downstream matching

No downstream operation may override the TenantId resolved from source ownership.

OBJECTIVE
Implement the tenant-owned inbound email source framework that allows each tenant to designate one or more authorized Synq Intake email addresses and associate each source with:
- tenant ownership
- source type
- email address
- provider
- purpose
- processing profile
- lifecycle status
- default-source status
- connector metadata/configuration
- configuration version

The completed framework must be able to answer:

“This recipient email address is a registered active Synq Intake source owned by Tenant X, serving Purpose Y, and using Processing Profile Z.”

without examining message content or sender identity.

==================================================

==================================================
5. GLOBAL EMAIL ADDRESS OWNERSHIP
==================================================

Normalized email address ownership must be globally unique inside Synq Intake.

Required invariant:

NormalizedEmailAddress -> exactly one TenantId

The same normalized email cannot belong to two tenants.

Example forbidden state:

Tenant A -> intake@example.com
Tenant B -> intake@example.com

Requirements:
- enforce uniqueness at application layer
- enforce uniqueness at database layer
- duplicate registration returns HTTP 409
- disabled sources retain ownership
- another tenant cannot claim an address merely because the current source is inactive
- do not silently reassign ownership

5. tenant profile assignment is enabled

Do not duplicate B02 profile configuration inside TenantIntakeSource.
